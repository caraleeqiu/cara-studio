# 语音派活：方案研究

目标一句话：**你用嘴派活，它调度几个 App 和 Agent 并行去干，干完推给你。**
最后把「按键说话」换成一个外接硬件。

日期：2026-09-05。这份文档只定方案，不写代码。第二版，按「派活」的场景重写。

---

## 为什么要做这个

三句话，每个设计决定都要对着它们检查：

1. **多线程。** 一天的活是并行的、跨 App 的。查东西的同时回邮件，还惦记着第三件。现在的工具是串行的，
   要么等，要么开一堆窗口自己记。
2. **不想打字。** 说比打便宜得多。把一句口语翻译成精确的 prompt，这个动作本身就是每次都要付的成本。
3. **不想切 App。** 切换是执行者的动作。派活的人只需要说一句、等结果、点头。

一句话概括：**把 Claude Code 从「坐在终端前用」变成「说一句、走开、回来点头」。**

由此推出三条硬约束，后面章节不许违反：

- **手机上能确认。** 走开了邮件写好了，不能非得回电脑说「发」。通知里带按钮。
- **交付物不是脚本。** 用户不写代码。Python 只是原型手段，交出去的必须是装上就能用的东西。
- **识别错了不靠打字纠正。** 输入本身就带错字，靠念回来确认和语义理解兜住，不靠改文字。

---

## 0. 定位

第一版把它当成「用嘴驱动的启动器」，切 App、听写、点界面。你给的例子把需求纠正了：

> 打开 Claude Code，帮我查个东西，查好了推我一条。同时打开 Gmail，把某某事办了。

这不是启动器，是**调度器**。启动器一次干一件事、当场干完。调度器把一句话拆成几件事，
派给不同的 worker，它们各干各的，谁干完谁汇报。语音只是派活的方式。

这个东西市面上没有现成的。Siri 只能单步，Raycast 只能跑预设脚本，Claude Code 本身要你坐在终端前。
**要自己做的是那个调度层**，worker 都是现成的。

## 1. 核心场景走一遍

把你那句话按时间线拆开，看每一步谁在干：

| 时刻 | 发生什么 | 谁干 |
|---|---|---|
| 0s | 按住键说：「打开 Claude Code 查一下 X，查好推我。同时打开 Gmail 把 Y 回了」 | 你 |
| 1s | 语音变文字 | 本地识别 |
| 2s | 文字拆成两个任务：A「用 Claude Code 查 X，完成后通知」、B「用 Gmail 回 Y」 | Claude 抽结构 |
| 2s | 屏幕上弹出两条任务卡，念一句「两件事，开始了」 | 调度器 |
| 2s | A 和 B **同时**起两个 Claude Code 会话 | 调度器 |
| 40s | B 先干完：Gmail 那封回好了（发之前停下来问你一句） | worker B |
| 90s | A 干完：查到了，结果三行 | worker A |
| 90s | Mac 弹通知，手机也收一条，桌面任务卡变绿 | 通知 |
| 随时 | 你问「查完了吗」，它答「A 还在跑，B 好了」 | 调度器 |

关键观察：**A 和 B 都不需要「打开」任何窗口。** Claude Code 有程序接口，Gmail 也有。
「打开 App」是人的习惯，程序不用打开就能干。想看着它干也可以开一个窗口，那是展示，不是必需。

## 2. 架构

```
 说话 ──► 本地语音识别 ──► 拆任务（Claude，输出 JSON）──► 调度器
                                                         │
                          ┌──────────────────────────────┼──────────────────────┐
                          ▼                              ▼                      ▼
                   worker：Claude Code            worker：本地动作          worker：点界面
                   （查资料、写东西、               （切 App、听写、          （没接口的 App，
                     Gmail、日历、文件）              开网页、跑脚本）           兜底用）
                          │                              │                      │
                          └──────────────► 完成 ◄────────┴──────────────────────┘
                                             │
                                   Mac 通知 + 手机推送 + 任务卡
```

原则只有一条：**能走接口就不点界面。** 接口稳、快、便宜，点界面慢、贵、会点错。
Claude Code 的接口是 `claude -p`，Gmail 的接口是 Claude Code 里的 Gmail 连接器。
点界面（辅助功能树加截图）留给真没有接口的 App，第一版不做。

## 3. 语音识别：走本地

和第一版结论一样，Actionway 不适合这一层，它的转写是给媒体文件用的。

| 方案 | 条件 | 中文 | 延迟 | 成本 |
|---|---|---|---|---|
| **Apple SpeechAnalyzer** | macOS 26 | 普通话、粤语 | 最快 | 0 |
| **whisper.cpp** | 任意 Apple Silicon | 好 | 短句 0.5 到 1 秒 | 0 |

派活的句子比听写长，一句二三十字，两种识别都够用。**要你确认 macOS 版本。**

## 4. 拆任务：Claude 结构化输出

一句话进来，Claude 输出一个任务列表，形状固定：

```json
{
  "tasks": [
    { "id": "a", "worker": "claude_code", "instruction": "查一下 X，给我三行结论",
      "notify": true, "needs_confirm": false },
    { "id": "b", "worker": "claude_code", "instruction": "用 Gmail 找到某某的最新一封邮件，回复 Y",
      "notify": true, "needs_confirm": true }
  ],
  "say": "两件事，开始了"
}
```

这就是现在 `voice_router/` 里那套东西，把 `Command` 换成 `TaskList`，路由表换成 worker 表。
`needs_confirm` 由模型判断：发邮件、删东西、付钱、发消息给别人，一律 true。

## 5. worker：三类

### 5.1 Claude Code（主力）

派活里八成的事都能交给它：查资料、写东西、看文件、Gmail、日历、Drive。

```bash
claude -p "查一下 X，给我三行结论" --output-format json
```

- 返回 JSON，`result` 字段是答案，`session_id` 能续。
- 并行就是同时起几个进程，互不干扰。
- Gmail 走 Claude Code 里的 Gmail 连接器（claude.ai 的 connectors，`/mcp` 里接）。
  不用自己搞 Google OAuth 那一套。
- 权限：`--permission-mode` 控制它能自己干多少。查东西给 `auto`，动邮件的任务让它停在发送前。
- 想看着它干：调度器可以同时开一个终端窗口 `--resume` 那个会话，纯展示。

登录：`claude -p` 用你的 Claude Code 订阅登录。Python 的 Agent SDK 官方文档要求 API key，
所以**第一版直接 shell 出去调 `claude -p`**，不用 SDK。够用，而且不多花钱。

### 5.2 本地动作（秒回的）

切 App、听写上屏、开网址、跑一条脚本。不走模型，调度器自己做：

- 切 App：`open -a WeChat`
- 听写：文本进剪贴板，发 Cmd+V，再把原剪贴板还回去。中文稳。
- 开网址：`open https://...`

### 5.3 点界面（兜底，第一版不做）

真没有接口的 App，用 [macos-use](https://macos-use.dev/) 读辅助功能树按名字点，截图兜底。
第一版不做，因为你举的例子里一个都不需要。什么时候有一个具体的 App 需要它再加。

## 6. 通知与回传

| 渠道 | 怎么做 | 什么时候用 |
|---|---|---|
| Mac 通知 | `osascript -e 'display notification ...'` 一行 | 每个任务完成 |
| 手机推送 | [ntfy](https://ntfy.sh/)：一条 curl，iOS 有 App，免费，**通知上能带「发 / 算了」按钮**，点了回调调度器 | 你不在电脑前，也是走开之后的确认入口 |
| 任务卡 | 桌面一个小浮窗，每个任务一行，跑着的黄、完了的绿、等确认的红 | 一直在 |
| 念出来 | macOS `say` 命令，或者不念只弹 | 短结论 |
| 问进度 | 「查完了吗」也是一句派活，worker 是调度器自己 | 随时 |

第一版就做手机推送，因为它同时是走开之后的确认入口。Mac 通知和任务卡一起做。

## 7. 安全

worker 在替你发邮件、动文件，这块不能后补。

- **`needs_confirm` 的任务在最后一步停下来**，进入 7.5 说的草稿循环。
  发送、删除、付款、给别人发消息，永远确认。
- **每个 worker 一个权限档**。查资料的会话只读；动邮件的会话只能动邮件。
  靠 `claude -p` 的 `--allowedTools` 和 `--permission-mode` 控。
- **一键停**。Esc 杀掉所有在跑的会话。
- 识别错了会派错活。拆任务之后先念一遍「两件事：查 X，回 Y」，三秒内没打断才开始。
  这三秒比事后收拾便宜得多。

---

## 7.5 确认不是按钮，是循环

`needs_confirm` 的任务干到最后一步不是停下来问「发不发」，是进入一个状态：

```
草稿 ──► 你看 ──┬── 「发」──► 执行 ──► 通知
                ├── 「算了」──► 作废
                └── 「改一下：语气软一点，时间改成周五」──► 改 ──► 草稿（回到开头）
```

改多少次都行，每次改完重新给你看。没说「发」永远不发，不设超时自动发。

**给你看什么**：任务卡上直接展示要发出去的东西，邮件就是收件人、标题、正文全文，
不是摘要。摘要看着没问题的邮件，正文里可能有一句错的。

**怎么改，三条路，都要有**：

| 方式 | 适合 | 怎么实现 |
|---|---|---|
| 说 | 「语气软一点」「删掉最后一段」这种模糊修改 | `claude -p --resume <会话> "改一下：…"`，同一个 worker 接着改，上下文都在 |
| 打字 | 改一个具体的词、一个数字 | 任务卡上的正文是可编辑的文本框，改完点发 |
| 在 App 里改 | 大改 | **草稿存在 App 自己那里**：Gmail 任务让 worker 建草稿而不是发送，你在 Gmail 里随便改，说「发」它把那条草稿发出去 |

第三条最重要，也最省事。草稿放在 Gmail 里，编辑器是 Gmail 自己的，你的修改不会丢，
调度器只需要记住草稿 id，「发」就是发那个 id。微信、Slack、日历都能照这个套路：
**worker 只准备，不准发；发的动作永远是你触发的那一下。**

发出去之前最后再展示一次当前版本，因为你在 App 里改过的和卡片上显示的可能已经不一样了。

任务 JSON 加一个状态字段：`running → draft → (revising → draft)* → done | cancelled`。

## 7.8 入口：Claude 不是入口

调度器常驻后台，开一个本机收件口（`127.0.0.1:8765/say`）和一个 ntfy 的 `-in` topic。
所有触发方式都只是往里投一句话，返回一句念回去的话：

| 入口 | 谁做语音识别 | 在哪用 |
|---|---|---|
| Siri + 快捷指令 | Siri，免费本地 | Mac 上「嘿 Siri，派活」，不开窗口 |
| iPhone 上的 Siri | Siri | 在外面派活，走 ntfy 中转 |
| 菜单栏图标 + 快捷键 | Mac 自带听写，或者 whisper | 桌前按住说 |
| 手机通知上的按钮 | 不用识别 | 走开之后确认 |
| 实体按钮 | 触发上面任一条 | 硬件阶段 |

Claude Code 只是被调度器叫起来干活的进程，你永远不用打开它。细节在 `docs/TRIGGERS.md`。

## 8. 形态

| 阶段 | 形态 |
|---|---|
| 原型 | Python 脚本，我用来验证链路。复用 `voice-router/`，加调度器和 `claude -p` worker |
| 交付 | Swift 菜单栏小程序，装上就能用：任务卡浮窗、全局快捷键、开机自启、权限一次授完 |

原型阶段的目标只有一个：证明「说一句、走开、回来点头」这条链路能跑通。跑通就转交付形态，不在脚本上打磨。

## 9. 硬件

硬件只换一环：**触发**。

- 最简单：ESP32 一个按钮，蓝牙模拟成键盘，按下发一个键，Mac 零改动。
- 进一步：盒子自带麦克风，离嘴近，识别率高。
- 再进一步：盒子有小屏，任务卡显示在盒子上，确认按钮也在盒子上。
  你不在电脑前，盒子还能替手机推送。

现在仓库里的 ESP32 固件是「Mac 发命令给板子」，方向反了，硬件阶段重写成「板子发触发给 Mac」。

## 11. 任务里点名了一个 App，怎么办

「用 Gmail 回老张」「在 Notion 里记一条」「切到微信发给他」。三个问题其实是一个：
**App 只是手段，任务要的是一种能力。** 邮件、消息、记笔记、看日历。同一种能力通常有好几条路到达，
worker 的活是挑一条走得通的，走不通换下一条，都走不通就诚实说。

### 11.1 能力阶梯：五级，从上往下试

| 级 | 通道 | 例子 | 速度 | 稳定 | 并行 |
|---|---|---|---|---|---|
| 1 | **接口 / MCP** | Gmail、Drive、日历、Slack、Notion、GitHub 的连接器 | 秒级 | 最稳 | 可以 |
| 2 | **脚本接口** | AppleScript / JXA、URL scheme、快捷指令、命令行 | 秒级 | 稳 | 可以 |
| 3 | **网页版** | 浏览器里操作 DOM。Gmail、Notion、Figma、飞书都有网页版 | 十秒级 | 中 | 可以（各开各的标签） |
| 4 | **图形界面** | 读辅助功能树按名字点，截图兜底 | 分钟级 | 差 | **不行**，屏幕只有一块 |
| 5 | **半自动** | 打开 App、切到对的地方、把内容粘好，最后一下你来 | 秒级 | 稳 | 不适用 |

第 2 级经常被忽略，其实很多 Mac App 都有：Mail、日历、备忘录、提醒事项、信息、音乐、Safari、Finder、
Things、OmniFocus、Bear 都能用 AppleScript 驱动，Claude Code 会写 `osascript`，不需要任何 MCP。
「没接 MCP」不等于「干不了」，多数时候是第 2 级或第 3 级的事。

第 4 级是真正的兜底，只给既没有接口、没有脚本、也没有网页版的 App。典型就是微信。

### 11.2 没有这个 App

先判断任务要的是 App 还是能力：

```
「用 Gmail 回老张」 ──► 要的是「回邮件」 ──► Mail.app 能不能？连接器能不能？网页版能不能？
「打开 Figma 导出」 ──► 要的是 Figma 本身 ──► 网页版能不能？不能就装
```

- **有替代就换**，换之前念一句「没装 Gmail，用 Mail 回，行吗」。三秒规则。
- **有网页版就开网页版**，走第 3 级。多数 SaaS 都有。
- **真要装**：`brew install --cask` 或 App Store，必须确认。装完要登录，登录必须你来。
- **都不行就说清楚**：「没装 X，也没有替代，要不要我装」。不装作干了。

### 11.3 切到 App 之后怎么执行

**切 App 和执行任务是两件事，多数时候不需要切。** 第 1 到 3 级根本不碰窗口，
第 2 级的 AppleScript 在后台就能让 Mail 发信。只有第 4 级要求 App 在最前面。

所以派活时区分两种意图：

- `switch_app`：你要**自己**看那个 App。秒回，切完就完。
- 在 App 里干活：走阶梯，窗口开不开由通道决定。想看着它干就顺手把 App 切到前面，纯展示。

第 4 级执行时的规矩：
1. 先切到前面，等一下界面稳了再读。
2. 每步之前重读界面，不按上一步的记忆点。
3. 弹了对话框先处理对话框。
4. 发送、删除那一下永远回到 7.5 的草稿循环。
5. **屏幕是独占资源**。第 4 级的活排队一个一个跑，第 1 到 3 级的活照常并行。
   两个第 4 级的活同时抢鼠标，两个都会坏。

### 11.4 没接 MCP

MCP 只是第 1 级的一种。没接 MCP，顺着阶梯往下：

| 情况 | 走哪级 |
|---|---|
| 有连接器但没接 | 提示你在 Claude Code 的 `/mcp` 里接一次，接完这个 App 永远走第 1 级。值得 |
| 没有连接器，是 Mac 原生 App | 第 2 级，AppleScript。让 worker 先 `sdef` 看它的脚本字典 |
| 没有连接器，是 SaaS | 第 3 级，网页版 |
| 什么都没有 | 第 4 级排队，或者第 5 级半自动 |

### 11.5 worker 怎么知道走哪级

两层：一张表加现场探。

**表**：`apps.json`，每个 App 一条，写清楚有哪几级。第一批填你常用的十个。

```json
"Gmail":  { "capability": "email", "web": "https://mail.google.com", "mcp": "Gmail", "applescript": false },
"Mail":   { "capability": "email", "bundle": "com.apple.mail", "applescript": true },
"微信":   { "capability": "message", "bundle": "com.tencent.xinWeChat", "gui_only": true },
"Notion": { "capability": "notes", "web": "https://notion.so", "mcp": "notion", "applescript": false }
```

`capability` 让「没装就换替代」能自动找到候选。

**探**：表里没有的 App，第一次用时探一遍：装没装（`mdfind`）、有没有脚本字典（`sdef`）、
有没有 URL scheme、连接器列表里有没有。探完写回表，下次不探。

**执行的地方**：不在调度器里写一堆 if，而是把阶梯写成 worker 的指令，Claude Code 自己顺着试：
「要在 App 上干活，按接口、脚本、网页、界面的顺序试，每一级失败就换下一级，最后报告走了哪级、哪些没做成。」
调度器只做两件快事：装没装、要不要排队。

### 11.6 几个真实的例子走一遍

**「用 Gmail 回老张说周五可以」**
Gmail 连接器接了：第 1 级，搜老张最新一封，写回复存草稿，给你看，说「发」再发。
没接：第 3 级，浏览器开 Gmail 网页，找到邮件，写回复，停在发送前。
Gmail 都没有：能力是「邮件」，问你「用 Mail 回行吗」。

**「微信发给小王：会议改到三点」**
微信没有任何接口，第 4 级。切到微信，搜小王，点进对话，粘贴内容，**停下来**。
你看一眼说「发」，它按回车。这就是第 5 级半自动，微信这种 App 现实的上限就是这样，
而且它比全自动更让人放心。

**「在 Notion 里记一条：下周找李总聊预算」**
Notion MCP 接了走第 1 级。没接走第 3 级网页版。记笔记不需要确认，记完通知。

**「打开 Figma 把首页导出 PNG」**
Figma 没装：有网页版，第 3 级，浏览器里开文件导出。导出不是发出去，不用确认。
文件落到下载文件夹，通知里带路径。

**「切到微信」**
就是 `switch_app`，秒回，没有后续。

### 11.8 怎么判断用哪个 App

四层，从最确定到最不确定，前一层定了就不看后一层：

| 层 | 依据 | 例子 | 谁定 |
|---|---|---|---|
| 1 | **点名了** | 「用 Mail 回」「vx 发给小王」。别名表把 vx、wechat、微信 都归成一个 | 别名表 |
| 2 | **从事推能力，查默认** | 「回邮件」→ email → 默认 Gmail；「记一条」→ notes → 默认 Notion | `apps.json` 的 defaults |
| 3 | **话里的线索** | 「老张微信上问我，回他」→ 微信；「回他」而前一句刚提过 Slack → Slack；当前前台是 Slack → Slack | 模型 |
| 4 | **问** | 「给小王发个消息」，消息类有微信、Slack、iMessage 三个，没线索 | 念回来时问「用微信还是 Slack？」 |

第 4 层的原则是**不猜**。猜错一个 App 的代价是消息发错地方，问一句的代价是两秒。
问完的答案写回 defaults，下次不问。

实现上：拆任务的 prompt 里带着 `apps.json` 的表，模型在每个 task 上填 `capability` 和 `app`，
填的名字过一遍别名表统一成标准名。worker 收到 `app` 后按 11.1 的阶梯挑通道。
没有模型时的兜底只做第 1 层和第 2 层。

`apps.json` 第一批放了十三个 App。**defaults 那几行是你的习惯，改成你自己的。**

### 11.9 唤醒 App、找到人：以微信为例

微信是最难的一个，没有接口、没有脚本、辅助功能树也只露一半。把它走通，别的 App 都是它的子集。
原则：**每一步先用最笨最稳的办法，笨办法失败了模型才上。** 模型每次上都要看屏幕、要花钱、会点歪。

#### 第一步：唤醒

```
open -b com.tencent.xinWeChat          # 没开就开，开了就切到前面
等 frontmost 变成微信，最多等 5 秒      # 用 System Events 查，不看截图
```

唤醒之后先判断它在哪个状态，三种：

| 状态 | 怎么看出来 | 怎么办 |
|---|---|---|
| 正常，主窗口 | 窗口标题是「微信」，有搜索框 | 往下走 |
| 没登录 | 窗口只有一个二维码或「手机确认登录」 | **停**，通知「微信要在手机上确认登录」，你登完说「继续」 |
| 弹了对话框 / 更新提示 | 最前面的窗口不是主窗口 | 先按 Esc 或点关闭，再看一次 |

#### 第二步：找人

微信 Mac 版有一个很稳的键盘路径，不用看屏幕：

```
Cmd+F            光标进搜索框
粘贴「小王」      不用逐字敲，剪贴板粘，中文不出错
等 0.5 秒         结果列表出来
```

到这里**必须看一眼**，因为结果可能是：一个人、好几个人、一个群、没有。

- 读辅助功能树拿到结果列表。微信的结果行一般能读到文字。
- 读不到就截一张图给模型，问「结果里有几个叫小王的，第一个是不是联系人」。

然后：

| 结果 | 怎么办 |
|---|---|
| 一个联系人，名字对上 | 回车，进对话 |
| 好几个 | 停，通知「有 3 个小王：小王(设计)、王小明、小王同学，哪个？」，你说了再走 |
| 只有群 | 你说的可能就是群，念一句「小王是群，对吗」 |
| 没有 | 停，「微信里没搜到小王」。多半是备注名不一样，见下面「人」的表 |

#### 第三步：验证进对了

回车之后再看一眼对话顶部的名字，和要找的人比一下。这一步不能省，
搜索结果的顺序偶尔会变，进错人是最坏的结果。名字对不上就退回第二步，还不对就停。

#### 第四步：粘内容，停

```
点一下输入框（或者进对话后光标默认就在那）
粘贴正文
停。不按回车。
```

这就是第 5 级半自动的终点：你看一眼，说「发」，它按回车。
微信这种 App，这一下留给人比全自动更让人放心，而且真的只差一个回车。

#### 「人」也要一张表

你嘴里的「老张」，在微信里是备注「张伟 DiDi」，在 Gmail 里是 zhang.wei@didi.com，在 Slack 里是 @weizhang。
每次让模型去猜，猜错就发错人。所以有 `people.json`：

```json
"老张": { "wechat": "张伟 DiDi", "email": "zhang.wei@didi.com", "slack": "@weizhang" }
```

查表命中直接用；没命中才按你说的名字搜；搜到了你确认过一次，就写回表。
用两周之后常联系的人都在表里了，找人这一步就不再需要看屏幕。

#### 配方，不是每次让模型想

上面四步对微信是固定的，写成配方放在 `apps.json` 里：

```json
"微信": { "recipe": {
  "activate": ["open", "-b", "com.tencent.xinWeChat"],
  "find":     ["key", "cmd+f", "paste", "{person}", "wait", "0.5", "check", "results"],
  "open":     ["key", "enter", "wait", "0.5", "check", "chat_title == {person}"],
  "compose":  ["paste", "{text}", "stop"]
}}
```

配方是一串确定的按键，跑一次几秒，不花钱。`check` 那几步才读屏幕，读不到才叫模型。
配方某一步失败了，模型接手那一步，成功之后把改好的配方写回去。
**第一次遇到一个新 App 让模型摸一遍写出配方，以后都是回放。**

#### 底层用什么

| 动作 | 工具 |
|---|---|
| 唤醒、切前台 | `open -b`，System Events 查 frontmost |
| 按键、粘贴 | System Events `keystroke`，剪贴板 `pbcopy` |
| 读结果列表、对话标题 | 辅助功能树，用 [macos-use](https://macos-use.dev/) |
| 读不到时看一眼 | `screencapture -x` 截图，给模型看图 |
| 权限 | 辅助功能、屏幕录制，各授一次 |

这些 Claude Code 在 Bash 里都能做，所以第 4 级不需要新 worker，只需要给它一个「Mac 界面操作」的技能说明，
把上面的规矩写进去。

### 11.7 还有几个坑，先记下

- **没登录**。App 装了没登录、网页版会话过期。worker 检测到登录页就停，通知你「X 要登录一下」，你登完说「继续」，`--resume`。
- **权限弹窗**。第一次用 AppleScript 控制某个 App，macOS 会弹「允许 Terminal 控制 Mail 吗」。交付形态里一次授完，原型阶段第一次跑会弹，点允许就行。
- **同一种能力好几个 App**。「回消息」是微信、Slack 还是 iMessage？表里放默认值（`"message": "微信"`），任务里点名了就用点名的，没点名用默认，拿不准问一句。
- **干完要验**。发了邮件去已发送里看一眼，记了笔记读回来。第 4 级尤其要验，因为它最容易点歪。通知里带验过的结果，不带「应该发了」。
